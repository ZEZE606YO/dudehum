# DUDEHUM — เว็บร้านขายของออนไลน์ + ระบบล็อกอินจริง

เว็บไซต์ร้านขายของออนไลน์บนช้อปปี้ หน้าเว็บทำด้วย HTML/CSS/JS
พร้อม **backend จริงด้วย Node.js** สำหรับระบบสมาชิก/ล็อกอิน — เก็บข้อมูลผู้ใช้ไว้ที่เซิร์ฟเวอร์จริง

> ✅ **ปลอดภัยต่อเครื่อง:** backend ใช้ **เฉพาะโมดูลที่มากับ Node.js** (`http`, `crypto`, `fs`)
> **ไม่มี npm package ของบุคคลที่สามเลยแม้แต่ตัวเดียว** จึงไม่มีความเสี่ยงเรื่อง supply-chain/มัลแวร์จากไลบรารีภายนอก

## จุดเด่นด้านความปลอดภัยของระบบล็อกอิน
- 🔒 รหัสผ่านเข้ารหัสด้วย **scrypt** + salt สุ่มรายคน (ไม่เก็บรหัสจริงลงไฟล์)
- 🍪 Session เป็น **cookie แบบ httpOnly** ที่เซ็นด้วย HMAC — JavaScript ฝั่งหน้าเว็บอ่านไม่ได้ (กัน XSS ขโมย token)
- 🛡️ เทียบรหัสผ่าน/ลายเซ็นด้วย `timingSafeEqual` (กัน timing attack) และมีการกัน path traversal ตอนเสิร์ฟไฟล์
- 👤 หน้า `account.html` ตรวจ session กับเซิร์ฟเวอร์ ถ้าไม่ล็อกอินจะเด้งไปหน้า login

## โครงสร้างไฟล์
```
landing-page/
├── index.html            # หน้าแรกร้าน DUDEHUM
├── login.html            # เข้าสู่ระบบ / สมัครสมาชิก
├── account.html          # หน้าบัญชีสมาชิก (ต้องล็อกอินก่อน)
├── css/style.css         # สไตล์ + design tokens
├── js/auth.js            # เรียก API ของ backend (fetch)
├── js/main.js            # theme toggle, เมนู, animation
├── server/
│   ├── server.js         # ⭐ backend จริง (Node.js built-in เท่านั้น)
│   └── data/             # สร้างอัตโนมัติ: users.json, secret.key
├── package.json
└── serve.ps1             # (ทางเลือกสำรอง) static server ไม่มี backend
```

## วิธีรัน (ต้องมี Node.js — ติดตั้งไว้แล้ว)
```bash
cd landing-page
npm start          # รันปกติ
# npm run dev      # โหมดพัฒนา: แก้ไฟล์ backend แล้วรีสตาร์ทให้อัตโนมัติ (node --watch)
```
แล้วเปิด http://localhost:5173

> แก้ไฟล์หน้าเว็บ (HTML/CSS/JS) → รีเฟรชเบราว์เซอร์เห็นผลทันที ไม่ต้องรีสตาร์ท
> แก้ไฟล์ backend (`server/*.js`) → ต้องรีสตาร์ทเซิร์ฟเวอร์ (หรือใช้ `npm run dev` ให้รีเองอัตโนมัติ)

> เซิร์ฟเวอร์นี้เสิร์ฟทั้งหน้าเว็บและ API ที่ origin เดียวกัน (ไม่ต้องตั้ง CORS)

## API
| Method | Path              | หน้าที่ |
|--------|-------------------|--------|
| POST   | `/api/register`   | เริ่มสมัคร → สร้าง pending + ส่ง OTP ทางอีเมล (ยังไม่สร้างบัญชี) |
| POST   | `/api/verify-otp` | ยืนยัน OTP → สร้างบัญชีจริง + ล็อกอิน (email, otp) |
| POST   | `/api/resend-otp` | ขอ OTP ใหม่ (มี cooldown 60 วิ) |
| POST   | `/api/login`      | เข้าสู่ระบบ (email, password) |
| POST   | `/api/forgot-password` | ลืมรหัสผ่าน → ส่ง OTP รีเซ็ตทางอีเมล (email) |
| POST   | `/api/reset-password`  | ยืนยัน OTP + ตั้งรหัสใหม่ + ล็อกอิน (email, otp, password) |
| POST   | `/api/logout`     | ออกจากระบบ (ล้าง cookie) |
| GET    | `/api/me`         | ดูผู้ใช้ที่ล็อกอินอยู่ |

## ลืมรหัสผ่าน (รีเซ็ตทางอีเมล)
- หน้า login มีลิงก์ **"ลืมรหัสผ่าน?"** → กรอกอีเมล → รับ **OTP 6 หลัก** → กรอก OTP + รหัสใหม่ → ตั้งรหัสใหม่สำเร็จและล็อกอินทันที
- ใช้กติกาเดียวกับ OTP สมัคร (หมดอายุ 10 นาที, ผิดเกิน 5 ครั้งยกเลิก, ขอใหม่ทุก 60 วิ), OTP เก็บ hash ใน `server/data/reset.json`
- **กันการเดาว่ามีบัญชีอยู่ไหม**: `/api/forgot-password` ตอบ success เหมือนกันทั้งกรณีมี/ไม่มีบัญชี (จะส่งเมลจริงเฉพาะเมื่อมีบัญชีเท่านั้น)

## ระบบยืนยัน OTP ตอนสมัคร
- สมัคร → ระบบส่ง **OTP 6 หลัก** ไปที่อีเมล (ยังไม่สร้างบัญชีจนกว่าจะยืนยันสำเร็จ)
- OTP หมดอายุใน **10 นาที**, กรอกผิดเกิน **5 ครั้ง** รหัสถูกยกเลิก, ขอรหัสใหม่ได้ทุก **60 วินาที**
- OTP ถูกเก็บแบบ **hash (scrypt)** ในไฟล์ `server/data/pending.json` (ไม่เก็บเป็นตัวเลขจริง)
- ระหว่างรอยืนยัน ข้อมูลอยู่ใน pending เท่านั้น เมื่อยืนยันแล้วจึงย้ายไป `users.json`

## ลองใช้ระบบล็อกอิน
1. เปิดเว็บ กด **"เข้าสู่ระบบ"** มุมขวาบน
2. แท็บ **"สมัครสมาชิก"** กรอกชื่อ/อีเมล/รหัสผ่าน (อย่างน้อย 6 ตัว)
3. เช็คอีเมล → เอา **OTP 6 หลัก** มากรอกในหน้ายืนยัน
4. ยืนยันสำเร็จ → ระบบสร้างบัญชีและพาเข้าหน้า **บัญชีของฉัน** อัตโนมัติ
5. ปิดเบราว์เซอร์แล้วเปิดใหม่ — ยังล็อกอินอยู่ (session 7 วัน) เพราะเก็บที่เซิร์ฟเวอร์จริง

> 💡 ถ้ายังไม่ได้ตั้งค่า Brevo (โหมดทดสอบ) จะไม่มีอีเมลส่งจริง — ดู OTP ได้จาก **console ของเซิร์ฟเวอร์** แทน

## ข้อมูลถูกเก็บที่ไหน
- บัญชีผู้ใช้: `server/data/users.json` (รหัสผ่าน hash แล้ว)
- กุญแจเซ็น session: `server/data/secret.key` (สร้างครั้งเดียวอัตโนมัติ — **ห้าม commit ขึ้น git สาธารณะ**)

## 📧 เปิดใช้การส่งอีเมลจริง (Brevo — ฟรี 300 ฉบับ/วัน)
ตอนนี้ระบบส่ง "อีเมลต้อนรับ" ให้อัตโนมัติเมื่อมีคนสมัครสมาชิก
ถ้ายังไม่ตั้งค่า จะเป็น **โหมดทดสอบ** (พิมพ์อีเมลลง console แทนการส่งจริง — ระบบไม่พัง)

**วิธีเปิดส่งจริง:**
1. สมัคร Brevo ฟรีที่ https://www.brevo.com (ไม่ต้องผูกบัตร)
2. ไปที่ **Senders, Domains & Dedicated IPs → Senders** แล้วเพิ่ม + ยืนยันอีเมลผู้ส่งของคุณ
   (เช่น `np.chinnakit@gmail.com` — Brevo จะส่งลิงก์ยืนยันไปที่อีเมลนั้น กดยืนยันให้เรียบร้อย)
3. ไปที่ **SMTP & API → API Keys → Generate a new API key** คัดลอกค่า (ขึ้นต้นด้วย `xkeysib-...`)
4. คัดลอกไฟล์ตัวอย่างเป็นไฟล์จริง แล้วใส่ค่า:
   ```
   server/data/mail.config.example.json  ➜  server/data/mail.config.json
   ```
   ```json
   {
     "provider": "brevo",
     "apiKey": "xkeysib-...ใส่ค่าจริง...",
     "senderEmail": "np.chinnakit@gmail.com",
     "senderName": "DUDEHUM"
   }
   ```
5. รีสตาร์ทเซิร์ฟเวอร์ (`npm start` ใหม่) แล้วลองสมัครสมาชิกด้วยอีเมลจริง → จะได้อีเมลต้อนรับเข้ากล่องจริง

> 🔐 ไฟล์ `mail.config.json` มีคีย์ลับ — ถูกใส่ใน `.gitignore` แล้ว **อย่า commit / อย่าแชร์ให้ใคร**
> ทางเลือก: ตั้งค่าผ่าน environment variables `BREVO_API_KEY`, `MAIL_SENDER_EMAIL`, `MAIL_SENDER_NAME` ก็ได้

## ⭐ เปิดเว็บให้ออนไลน์ (วิธีง่ายสุด — ดับเบิลคลิก)
เพื่อให้เว็บออนไลน์แบบไม่ผูกกับ Claude Code (อยู่ได้ตราบใดที่ไม่ปิดหน้าต่าง):
1. ดับเบิลคลิก **`เปิดเว็บ.bat`** → เปิดเซิร์ฟเวอร์ (หน้าต่างนี้ต้องเปิดค้างไว้)
2. ดับเบิลคลิก **`เปิดลิงก์สาธารณะ.bat`** → เปิด tunnel ได้ลิงก์ให้คนอื่นเข้า
   - ถ้า cloudflared ตัวเก่ายังรันอยู่ ลิงก์เดิมใช้ได้เลย ไม่ต้องเปิดซ้ำ
3. เข้าเว็บได้ที่ http://localhost:5173 (ในเครื่อง) หรือลิงก์ trycloudflare (จากที่อื่น)

**ปิดเว็บ** = ปิดหน้าต่างสองอันนั้น • **เปิดใหม่หลังรีสตาร์ทคอม** = ดับเบิลคลิกใหม่

> ⚠️ ทุกครั้งที่เปิด tunnel ใหม่ ลิงก์จะเปลี่ยน — อัปเดต `publicUrl` ใน `server/data/mail.config.json` ให้ตรง

## 🌐 เปิดให้เข้าผ่านลิงก์ (Cloudflare Tunnel — ฟรี ไม่ต้องสมัคร)
ทำให้คนอื่นเข้าเว็บได้ผ่านลิงก์ `https://xxxx.trycloudflare.com` โดยเว็บยังรันบนเครื่องคุณ

1. ติดตั้งครั้งเดียว: `winget install Cloudflare.cloudflared`
2. เปิดเซิร์ฟเวอร์เว็บ: `npm start` (พอร์ต 5173)
3. เปิดอีกหน้าต่าง แล้วรัน: `powershell -ExecutionPolicy Bypass -File share.ps1`
4. รอสักครู่จะได้ลิงก์ → ส่งให้ใครก็ได้เข้าเว็บ

> ⚠️ ลิงก์ใช้ได้ตราบใดที่ **คอมเปิด + เซิร์ฟเวอร์รัน + cloudflared รัน** อยู่
> ลิงก์จะ**เปลี่ยนใหม่ทุกครั้ง**ที่เปิด tunnel ใหม่ — ถ้าเปลี่ยนแล้ว อย่าลืมอัปเดต `publicUrl`
> ใน `server/data/mail.config.json` ให้ตรงลิงก์ใหม่ (เพื่อให้ปุ่มในอีเมลลิงก์ถูก)
>
> ถ้าอยากได้ลิงก์ถาวร รัน 24 ชม. โดยไม่ต้องเปิดคอม → ต้องใช้โฮสต์จริง (ดูหัวข้อถัดไป)

## จะเอาขึ้น production จริงควรทำเพิ่ม
- เปลี่ยนเก็บข้อมูลเป็นฐานข้อมูลจริง (เช่น SQLite/PostgreSQL) แทนไฟล์ JSON
- รันหลัง HTTPS แล้วเพิ่ม flag `Secure` ให้ cookie
- ใส่ rate-limit กันเดารหัสผ่าน
